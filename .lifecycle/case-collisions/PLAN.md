# PLAN.md — case-collisions

Fix the component/store case collisions that make `src-app/ui` build only on a
case-sensitive filesystem, and add a guard so the class cannot silently return.

## Design source

Realizes `/data/khoi/home-workspace/paws-worker-tasks/case-collisions.md` §1 (the
problem + the already-established facts), §2 (*Required approach* + *Add a regression
guard*), §3 (*Verification*) and §4 (*Scope discipline*). That brief is the design of
record for this branch: it carries the diagnosis, the macOS evidence
(`https://github.com/tinnlab/paws/actions/runs/32516353496`, job
`dev build aarch64-apple-darwin`), and the 91-store precedent the approach is derived
from. There is no separate upstream design doc and none was invented.

Supporting sources the plan is reconciled against (not the design, but binding
context): `src-app/desktop/ui/docs/UI_OVERRIDES.md` (the tier-1/2/3 resolver),
`CLAUDE.md` (UI Build Gate, `npm run check`), and
`agent-kit/docs/CODING_GUIDELINES.md` §9 (canonical frontend module layout) / §15
(dead code = unfinished work).

## Invariants

Lifted VERBATIM from the design source (`case-collisions.md` §2).

- **INV-1**: Eliminate every case collision (re-run the detector to prove 0 remain).
- **INV-2**: Survive `npm run gen:store-actions` — regenerate and confirm the output is stable and `check:store-actions` passes. A fix that codegen reverts is not a fix.
- **INV-3**: Update every import site in **both** `src-app/ui/src` and `src-app/desktop/ui/src` (desktop consumes ui via the `@/…` alias and the tier-1/2/3 override resolver — see `src-app/desktop/ui/docs/UI_OVERRIDES.md`).
- **INV-4**: Use `git mv` so history follows the files.
- **INV-5**: Add a check that FAILS when any `Foo.tsx` sits beside a `foo/` directory differing only in case, and wire it into `src-app/ui`'s `npm run check` (and desktop's, if applicable).
- **INV-6**: the guard must read from a PERMANENT committed path, never from `.lifecycle/` (which is stripped at merge; a gate reading it passes in your worktree then fails on main forever). Verify it against a lifecycle-stripped tree before declaring done.
- **INV-7**: Conform to the existing majority convention rather than inventing a new one.

Two facts the design did NOT state, found here and load-bearing:

1. **`src-app/ui/src/modules/llm-provider/components/ProviderGroupAssignmentCard.desktop.tsx` exists** — a tier-2 desktop override that is a sibling of one of the 24 colliding component files. The desktop resolver's `probeDesktopInfix` probes `providerGroupAssignmentCard.desktop.tsx` **before** `providerGroupAssignmentCard/index.ts`, so on a case-insensitive FS the *store* specifier case-matches that `.desktop.tsx` too. Moving the store fixes this second resolution path as well; nothing about the override itself changes.
2. **`src-app/ui/src/modules/layouts/app-layout/appLayout/index.ts` has a module-scope side effect** — `appLayoutSeam.set(AppLayout)`. It is import-order-sensitive, so the move must preserve *which module* is imported at each site, not merely make it type-check. (It does: every site is rewritten one-for-one; no site is added, removed, or reordered.)

- **ITEM-5**: Add the regression guard `src-app/ui/scripts/lint-case-collisions.mjs` — walks `src-app/ui/src` and `src-app/desktop/ui/src` and FAILS (exit 1, naming both paths) when any source file's basename is case-insensitively equal to, but case-sensitively different from, a sibling directory name.
- **ITEM-6**: Register the guard: `check:case-collisions` + `test:case-collisions` in `src-app/ui/package.json`, appended to its `check` chain; and `check:case-collisions` in `src-app/desktop/ui/package.json`'s `check`, invoking the same single ui-tree script (`node ../../ui/scripts/lint-case-collisions.mjs`) rather than forking it.

- **ITEM-8**: Add `src-app/ui/tests/e2e/visual/store-case-collision.spec.ts` — a backend-free gallery spec that, in a real browser, opens each relocated store's overlay surface through its **store action** and asserts the drawer renders; a specifier that had resolved to the component instead of the store would have no such action and the case would fail.
- **ITEM-9**: Add `src-app/ui/scripts/lint-case-collisions.tsc.test.mjs` — spawns `tsc --noEmit` in BOTH `src-app/ui` and `src-app/desktop/ui` and asserts exit 0, which is the authoritative oracle that every import site in both workspaces resolves after the move (INV-3). Deliberately NOT chained into `npm run check` (which already runs `tsc` as its first step in each workspace); it is enumerated in TESTS.md and run at phase 8.
- **ITEM-10**: Physically verify INV-6 against a lifecycle-stripped tree — move `.lifecycle/` aside, re-run `npm run check:case-collisions` in both workspaces, confirm exit 0 — and record the observed output in `TEST_RESULTS.md`.
- **ITEM-11**: **[ADDED IN PHASE 7, ROUND 1 — see FIX_ROUND-1.md]** Eliminate the **25th** case collision. It is the same bug class in a different shape, and the phase-5 detector's file-vs-*directory* framing could not see it: `modules/workflow/components/builder/AgentStepForm.tsx` (the component) sits beside `agentStepForm.ts` (its pure helpers), and `.ts` is probed BEFORE `.tsx`, so `./AgentStepForm` resolves to the HELPERS on a case-insensitive filesystem. Rename the helper and its test to `agentStepForm.helpers.ts` / `agentStepForm.helpers.test.ts` — mirroring the existing `messageViewState.helpers.ts` and `downloadProgress.helpers.ts` — and update its two import sites. Without this, the macOS build still fails and **INV-1 is not met**.
- **ITEM-12**: **[ADDED IN PHASE 7, ROUND 1]** Widen the guard from one rule to **three, one per real resolver probe**, so it can see the shape ITEM-11 fixes and the shapes adjacent to it: (a) file-vs-file resolver-stem collisions; (b) the desktop resolver's `.desktop` infix — `X.desktop.tsx` answers to the bare specifier `X`, so it collides with a sibling `x/`, a pair that was live on `origin/main`; (c) full-name case duplicates, evaluated FIRST as the strictly worse diagnosis. Make it **fail closed** on any root or directory it cannot walk (it previously printed OK after scanning nothing), report **per-root** counts, dedupe roots and findings, classify symlinks, and cover every tree the two UI builds actually compile — both `src`, both `tests`, and every `sdk/packages/*/src`.

## Patterns to follow

- **Store location** — mirror the 91 existing `**/stores/<storeName>/` stores. Closest
  exemplars: `src-app/ui/src/modules/user/stores/users/` (module-root `stores/`),
  `src-app/ui/src/modules/chat/core/stores/splitView/` (sub-layer `stores/`), and
  `src-app/ui/src/modules/host-mount/project-extension/stores/projectHostMounts/`
  (extension-dir `stores/`, in the desktop tree). Those three prove `stores/` already
  sits at **varying depths**, so a `stores/` directory beside the component is
  *within* the existing convention rather than a new one — which is exactly what
  INV-7 asks for. Co-location with the component is preserved.
- **Guard script** — mirror `src-app/ui/scripts/lint-icon-action.mjs` and
  `src-app/ui/scripts/gen-override-registry.mjs`: `.mjs` under `src-app/ui/scripts/`,
  a block-comment header naming the bug it closes and the run line, roots anchored to
  the script's own location (`HERE/../src`, `HERE/../../desktop/ui/src`) so it is
  CWD-independent, collect-every-violation-then-one-`process.exit(1)`, and a single
  `✓` line on success.
- **Guard's anti-no-op test** — mirror `src-app/ui/scripts/lint-hooks-top-level.test.mjs`
  and its `test:hook-gates` registration: a `node --test` suite that proves the gate is
  enabled, wired into `check`, and goes RED on a real violation.
- **Desktop reuse of a ui-tree guard** — mirror
  `src-app/desktop/ui/package.json`'s existing
  `"check:override-registry": "node ../../ui/scripts/gen-override-registry.mjs --check"`.
  One script, two registrations; **do not fork** (CLAUDE.md's "One harness, not
  several" — the forked-harness class this repo has already paid for twice).
- **Gallery e2e spec** — mirror `src-app/ui/tests/e2e/visual/overlays.spec.ts` and
  `states.spec.ts`: `playwright.visual.config.ts` (backend-free), the `openGallery`
  helper from `./_gallery`, portal-scoped locators, `--workers=1` at phase 8.
- **Import style** — keep each site's existing form. An `@/…` site stays `@/…`; a
  relative site stays relative. Converting an alias import to a relative one would
  silently disable any tier-2 `.desktop.tsx` override (the barrel caveat in
  `UI_OVERRIDES.md`), so the rewrite is a path substitution and nothing else.

# Plan audit (phase 2) — verdicts against the codebase

## Breakage risk

- **The store's public surface is unchanged.** Each `index.ts` keeps its exports
  (`export const Foo = registerLazyStore(FooDef)`, `export const useFooStore =
  FooDef.store`, plus the 6 dirs that also export `FooDef` / an alias). Only the
  *path* changes, so every consumer keeps the same imported binding.
- **Intra-store imports are all store-relative** (`./state`, `./actions.gen`,
  `import.meta.glob('./actions/*.ts')`) and therefore move with the directory
  untouched — verified by reading `editUserDrawer/index.ts` and its `actions.gen.ts`.
- **No deep imports into a store dir exist** (`grep -rn '<storeName>/'` across
  `src-app` returns nothing), so no consumer reaches past `index.ts`. The rewrite is
  therefore a whole-specifier substitution with no sub-path fan-out.
- **`appLayout`'s module-scope `appLayoutSeam.set(AppLayout)` side effect** is the one
  ordering-sensitive store. Risk is mitigated by rewriting sites one-for-one (no site
  added/removed/reordered) — but it is the reason ITEM-8's live-render e2e exists
  rather than trusting `tsc`.
- **A new sibling `stores/` directory could itself collide** with a sibling
  `Stores.tsx`/`stores.ts`. None exists today; the ITEM-5 guard re-run after the move
  is what proves it (and would catch it if a future one appeared).
- **Residual risk this branch cannot retire locally:** the only authoritative proof is
  a macOS build, which this Linux box cannot produce (no Darwin std / Xcode). Recorded
  as `NOT VERIFIED` in `TEST_RESULTS.md` for the lead to dispatch — never as a PASS.

## Pattern conformance

- Conforms to the dominant convention (91 + 5 stores under a `stores/` parent) rather
  than inventing a suffix. INV-7 satisfied by *joining* the majority, and the
  varying-depth precedent (module-root / sub-layer / extension-dir `stores/`) is what
  makes a component-sibling `stores/` conformant rather than novel.
- Guard placement, arg style, exit convention and registration all mirror named
  existing scripts (listed under *Patterns to follow*).
- `agent-kit/docs/CODING_GUIDELINES.md` §9 (canonical frontend module layout names
  `stores/` as the store home) is upheld, not merely unbroken.

## Migration collisions

**None — this branch adds no migration.** Server max at branch time is
`202607200600`; desktop remains in its `1e13` block. See `BASE.md`.

## OpenAPI regen

**Not implied.** No Rust type, handler, or schema changes; neither
`**/openapi/openapi.json` nor `**/api-client/types.ts` is touched. `just openapi-regen`
is not run (and `just` is absent on this box — recorded in STATUS).
