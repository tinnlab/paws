# DRIFT-3 — implementation vs plan, round 3 (post second blind audit)

- **DRIFT-3.1** — verdict: plan-wins — the plan's INV-1 requires that a refetch is never served pre-change data. The second blind round found a THIRD path the freshness window could not see: an identity change that happens through neither an HTTP mutation nor a sync frame — a local `endSession()` teardown (which clears `user`/`permissions` with no request at all) and the desktop/tunnel `setAuthFromAutoLogin` seeding a whole new session over Tauri IPC. Both would have left the window armed over a store that no longer holds that identity. Added `invalidateMeFreshness()` and called it from both, with an acceptance case.
- **DRIFT-3.2** — verdict: plan-wins — `refreshCurrentUser` had silently changed its public contract (from "always fetches" to "may resolve without a round-trip") with no opt-out, in a store file shared verbatim by `src-app/ui` and `src-app/desktop/ui`. Added `{ force: true }`, documented on the interface, beating BOTH the in-flight join and the freshness skip.
- **DRIFT-3.3** — verdict: plan-wins — ITEM-1's exclusion list was closed (`GET` ∧ ¬SSE ∧ ¬FormData) with no per-call escape. In a transport shared by three applications a caller with a genuine reason (a one-shot nonce, a poll whose point IS the round-trip) must be able to decline without editing the transport. Added `callbacks.noCoalesce`.
- **DRIFT-3.4** — verdict: impl-wins — the plan's key design said "the resolved path/query is a pure function of the endpoint + params", and round 1 added the resolved ORIGIN to the key on the theory that desktop's Tauri port could change mid-session. Verified against `getBaseURL.ts` / `getBaseURL.desktop.ts`: both memoize the base URL in a module-scoped promise for the page's lifetime, so it CANNOT change. The extra `await getBaseUrl()` was pure cost on every joinable GET — and removing it moved the shell's first data request on `/` from 438 ms to **75 ms**, because that resolver hop sat on the boot critical path. PLAN's key description amended.
- **DRIFT-3.5** — verdict: plan-wins — three tests were doing less than they claimed and were rewritten to actually discriminate: TEST-12 asserted the value the test itself had typed (so it passed before any refetch resolved and could never see a coalesced response — it now waits for the post-save `/me`); TEST-11's exact `=== 1` was coupled to the 3 s window rather than to the invariant (now conditioned on the observed inter-call gap); and TEST-14 asserted formatting-coupled regexes plus a three-identifier denylist (now asserts the `isAuthenticated:` value EXPRESSION, so a reintroduction under any name fails and a reformat does not).
- **DRIFT-3.6** — verdict: plan-wins — the plan put ITEM-7's decision logic inline in the store, and the audit correctly noted the store's own spec cannot load in this tree, so the three new branches shipped with no unit coverage. Extracted `canJoinMeRefresh()` / `shouldSkipMeFetch()` as pure predicates the store calls, and covered them. Same shape as DRIFT-1.1/1.2/1.3: when a decision is not testable where it sits, move the decision, not the test.
- **DRIFT-3.7** — verdict: resolved — smaller repairs: a non-joinable entry is now EVICTED rather than merely refused (it would otherwise leak one Map entry per hung read for the page's lifetime); a deterministic resolve failure is memoized after one retry so an authoring bug cannot become an unbounded retry loop; `isDev()` is used in the HMR branch too; `performCall` uses the guarded `isFormData()`; the dead `setAuthView`/`evaluatePermission` stub exports were removed.
- **DRIFT-3.8** — verdict: none — four comments were making claims the code did not support (the `FormData` rationale, the origin-in-key rationale, `MAX_JOIN_AGE_MS`'s sizing, `inflightKey`'s "never", the stub's "removes reachability entirely", the HMR scope, and the backoff test's escalation claim). All corrected to say what is actually true, including naming one exposure as KNOWN and UNFIXED with its reason. A comment that overstates is a defect in a shared package — the next reader trusts it.
- **DRIFT-3.9** — verdict: none — a third confirmation audit pass was attempted and DISCARDED: the shared backend on `:29185` (owned by another session) went down partway through, so the run measured a dead backend. Recorded rather than quietly dropped; the two complete paired runs and the boot-probe medians all predate the outage.
