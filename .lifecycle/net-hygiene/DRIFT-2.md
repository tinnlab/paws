# DRIFT-2 — implementation vs plan, round 2 (post blind-audit + rebase onto the new base)

- **DRIFT-2.1** — verdict: plan-wins — the blind audit found `callAsync` had been converted from `async` to a plain arrow so the coalescing prologue could run before the promise. That silently changed the transport's contract for all three consumers: a synchronous throw in the prologue (`params instanceof FormData` with no global `FormData`, a throwing token provider, a refused `localStorage` read) escaped the call site instead of rejecting, so every `ApiClient.X.y(...).catch(...)` lost that path. Re-implemented as the plan required — the function is `async` again and the coalescing happens inside the async body.
- **DRIFT-2.2** — verdict: plan-wins — ITEM-4's cold-window merge was **removed entirely**, not repaired. Two independent audit angles showed it violated the plan's own stated rule ("a mutation must never be silently collapsed into another's"): the dispatcher cannot tell a read from a mutation, so two deliberate identical mutation dispatches during the chunk load collapsed into one and BOTH callers resolved successfully; and `JSON.stringify` does not throw on a function, so two calls carrying different callbacks keyed identically and the second callback never ran. The duplicate NETWORK requests it was chasing are already removed one layer down by ITEM-1, where "is this a read?" is knowable. `lazy-dispatch.ts` remains as a pure extraction (chunk memoization + `preload`), plus a real improvement the audit surfaced: a FAILED chunk load is no longer memoized, so a transient 404 cannot brick an action for the session.
- **DRIFT-2.3** — verdict: plan-wins — ITEM-8's bare `if (s.loading) return` on `notification-ui`'s `load` was **reverted**. It looked like the sibling list-action guard the plan cited, but this action reads `page`/`perPage`/`unreadOnly` from state and `setPage`/`setUnreadOnly` mutate those and then call it — so a page change or filter toggle was dropped (UI on the new selection, old items), and the `sync:notification` / `sync:reconnect` reload wired in `../index.ts` was dropped too. That is a direct INV-1 violation (a missing refetch is worse than a duplicate). The identical-concurrent case it was meant to fix is handled by the transport, which can distinguish them. TEST-10a was rewritten to assert the differing-intent reload IS issued — it now fails on the old behaviour.
- **DRIFT-2.4** — verdict: plan-wins — `meFreshness.noteMeLoaded` stamped the epoch at RESPONSE time, the inverse of the guard `coalesce` gets right. A `/me` in flight when a mutation completed was recorded with the post-mutation epoch and marked fresh, so the refresh that mutation triggers would have been suppressed and the UI would keep pre-mutation data. Now the epoch is captured at REQUEST time (`meRequestEpoch()`), with a dedicated acceptance case.
- **DRIFT-2.5** — verdict: plan-wins — `refreshCurrentUser`'s pre-existing `if (refreshInFlight) return refreshInFlight` had no epoch check while the freshness guard added right below it did, so a caller arriving after a mutation still joined a pre-mutation `/me`. INV-1 was half-enforced in the very store the feature targets. The join now also requires the current epoch.
- **DRIFT-2.6** — verdict: plan-wins — `reconnectDelayMs`'s 429 branch ignored `currentBackoffMs`, so once the transient ladder had escalated to 30 s a capacity refusal SHORTENED the wait to ~12 s and never escalated again — retrying faster against an endpoint that had just refused, the opposite of ITEM-9's stated intent. Now `min(max(currentBackoffMs, capacityFloor), MAX)`, with a test that pins the raise-the-floor property.
- **DRIFT-2.7** — verdict: plan-wins — the permissions unit-test stub had been placed under `sdk/packages/framework/src/`, whose export map is `"./*": "./src/*"` — making an always-allow `hasPermissionNow` a RESOLVABLE PUBLIC SUBPATH of the shared package for all three consuming apps, with nothing preventing an import that disables every permission check. Moved into the app's own test tree (`src-app/ui/src/core/__test-stubs__/`), which is not a published package.
- **DRIFT-2.8** — verdict: plan-wins — **ITEM-6 was DESCOPED** (PLAN + DEC-15 + an approved `DESCOPED:` disposition). Three angles independently flagged that deriving `isAuthenticated` from a persisted token delivers and initializes the whole authenticated-tier module surface to a holder of a revoked-but-unexpired token, that `expiresAt: null` is the current shape and not only a legacy one, and that it contradicts this branch's own desktop reasoning. Decisive: re-measuring with it removed showed **no change to any metric it was meant to move**. Its tautological acceptance test (TEST-6 hardcoded `can: () => false` and never touched `buildLoadContext`) is replaced by TEST-14, which asserts the widening stays OUT.
- **DRIFT-2.9** — verdict: none — the audit's `waterfall` and `failure` metrics moved in OPPOSITE directions across two paired A/B runs whose only difference was run ORDER (`failure` 13→25 one way, 29→25 the other; `maxWaterfallDepth` 9→13 one way, 16→10 the other), driven by the shared backend's SSE connection pool still being saturated from whichever run went first (`/api/sync/subscribe` → 429: 3 vs 14 on the SAME build). `duplicate` → 0 in BOTH after-runs. Recorded so the results report the stable signal and refuse to claim the unstable ones in either direction.
- **DRIFT-2.10** — verdict: impl-wins — the branch was merged onto the new `origin/feat/agent-core` tip (`a72553e6e`) mid-lifecycle, because the concurrent branch's two excluded fixes LANDED there. Both audits were re-run against that tip so the baseline already contains the by-conversation batch endpoint and the llm-model catalog, and this branch is credited with neither. The merge was clean; no conflict, no `openapi.json` / `api-client` regen on this side. BASE.md and the diff base for every gate move from `60b0db310` to `a72553e6e` accordingly. The other feature's `.lifecycle/live-ui-audit-fixes/` came in with the merge and was stripped (a branch carries exactly one).
- **DRIFT-2.11** — verdict: resolved — smaller audit-driven repairs, each with a test: the coalescing key now includes the RESOLVED BASE URL (desktop's Tauri port can change across a server restart); an entry stops being joinable after `MAX_JOIN_AGE_MS` (the transport sets no fetch timeout, so a hung GET otherwise pinned its key forever and made that endpoint permanently unreadable on a quiet page); a joiner receives an ISOLATED copy rather than aliasing the issuer's parsed object; `__resetInflightForTests` bumps rather than rewinds the monotonic epoch; the HMR branch of `registerModule` no longer replaces a self-owned proxy either (tracked via `selfOwnedStores`) and warns on a genuine store-name collision; the `LazyDispatcher` type was renamed `LazyActionDispatcher` to stop colliding with store-kit's same-named public type; `syncBackoff.test.ts` imports `MAX_BACKOFF_MS` instead of re-declaring it; TEST-9 now asserts the sdk submodule was actually scanned instead of silently skipping it; and the e2e restores the shared fixture user in a `finally`.
- **DRIFT-2.12** — verdict: none — two findings are deliberately NOT fixed, recorded so the decision is visible rather than an omission. (a) The freshness epoch is GLOBAL, so an unrelated sync frame or POST disables coalescing for every key; narrowing it per-entity is the direction that would risk a stale join, and over-invalidation is the safe failure mode under INV-1. (b) The transport coalescer is unconditional over GETs, so it also collapses concurrent `/api/llm-models` — an endpoint owned by the other branch. A per-endpoint carve-out in a shared transport is exactly the hidden cross-module coupling the guidelines forbid; DEC-11 records the choice and the results report it explicitly so their measurement is not silently confounded.
