# DESIGN_FIDELITY — net-hygiene

One verdict per invariant in `PLAN.md` § Invariants, checked against the plan
(not against the code — that is the phase-6 `design-conformance` angle's job).

- **INV-1** — fidelity: UPHELD — the plan never introduces a cache or a TTL; ITEM-1 only ever JOINS a request that is literally in flight, and ITEM-2's freshness epoch makes it impossible to join one that started before a mutation the caller made or before an inbound sync frame. Every store keeps its `sync:<entity>` / `sync:reconnect` subscription and still issues a real refetch on each — the plan changes no store's subscription and removes no refetch call site. ITEM-7 is the only place a refetch is skipped, and DEC-5 scopes that skip to a boot window that provably contains a `/me` with identical content. Pinned by TEST-2 + TEST-3 + TEST-7 (`[acceptance]`).
- **INV-2** — fidelity: UPHELD — the plan attacks the chain at its measured head: `/api/auth/me` is moved off the router-mount critical path (ITEM-5) so it OVERLAPS `/api/app/setup/status` and `/api/onboarding/progress` rather than following them, and ITEM-6 stops auth-gated module registration being strictly downstream of that response. Nothing is parallelized that genuinely depends on a predecessor: permission-gated modules still wait for real permissions (INV-5), and every store still fetches only once its own gate passes. Pinned by TEST-5 (`[acceptance]`, e2e — asserts real time-overlap in the browser).
- **INV-3** — fidelity: UPHELD — the de-dup is implemented ONCE, at the shared transport (ITEM-1/2/3) plus the shared dispatch layer (ITEM-4), rather than as N per-caller patches; that is literally the "one shared in-flight request de-dupe rather than N independent callers" the invariant asks for. The two residual point fixes (ITEM-7, ITEM-8) address duplicates that are NOT concurrent and therefore genuinely cannot be coalesced. Pinned by TEST-1 (`[acceptance]`).
- **INV-4** — fidelity: UPHELD — no plan item names, imports, or edits a `/api/projects/by-conversation` or `/api/llm-models` call site; `## Files to touch` contains none, and no `openapi.json` / `apiEndpoints.ts` / `types.ts` regen is implied (PLAN_AUDIT § OpenAPI regen). Because ITEM-1 is a generic transport layer, `/api/llm-models` will be *incidentally* coalesced when its three callers fire concurrently — that is a side effect of a layer, not a change to the excluded fix, and the results must report the excluded endpoints separately so the other agent's before→after stays readable. Pinned by TEST-9 (`[acceptance]`, mechanical diff check).
- **INV-5** — fidelity: UPHELD — ITEM-6 widens ONLY `isAuthenticated`, derived from a live persisted token. Permissions are deliberately left non-persisted, so `isEligible`'s `ctx.can(Permissions.X)` still evaluates against an empty permission set until `/auth/me` lands, and a permission-gated module's chunk is still never delivered to a user who lacks the permission. The plan explicitly rejects the faster alternative (persisting permissions) for exactly this reason, in DESIGN § Non-negotiables. Pinned by TEST-6 (`[acceptance]`).
