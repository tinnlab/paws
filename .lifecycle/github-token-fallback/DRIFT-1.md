# DRIFT-1 — implementation vs plan/design

Authored during phase 5, item by item, as each landed.

- **DRIFT-1.1** — verdict: impl-wins — PLAN ITEM-3 said `github_get_with_retry` would return `(reqwest::Response, CredentialStatus)`, i.e. the status inside the `Ok`. Implementing it showed that shape LOSES the verdict on exactly the case that matters: a transport error on the anonymous retry (`result?` propagates and drops `credential`), and a `list_releases` early-`?`. Since a failed read is precisely when the operator needs to be told their token was rejected, the signature became `(Result<reqwest::Response>, CredentialStatus)` — the status rides ALONGSIDE the result, and is known whether the read succeeded or failed. `list_releases` and `get_or_refresh`'s injected `fetch` follow the same rule. PLAN ITEM-3/ITEM-5 amended to match; the design (§5) is unaffected — it only ever required the fact be reportable.
- **DRIFT-1.2** — verdict: impl-wins — PLAN ITEM-5 said a cache hit reports "the credential status of the fetch that produced the entry", and DEC-8 says the same. That is right for the fresh-hit path but WRONG for retain-on-failure: if a token is revoked after an entry was cached, the failing refresh knows it was `Rejected` while the stored entry still says `Used`, and echoing the stored value would mask a live problem behind a stale verdict. Implemented as: fresh hit ⇒ the stored verdict; retain-on-failure ⇒ the FAILED refresh's verdict. Both halves are asserted in TEST-7. DECISIONS DEC-8 amended.
- **DRIFT-1.3** — verdict: plan-wins — a first pass let rustfmt reformat all five touched Rust files, producing a 792-line diff (103 lines in `binary_manager.rs`, 257 in `handlers.rs`) for ~22 lines of real change. That is not what the plan scoped and it would have swamped the phase-6 audit. Reverted; the edits were re-applied without whole-file formatting, and the result was verified formatting-neutral: `download.rs` shows 175 rustfmt diff lines both BEFORE and AFTER the change (identical count, and `grep` confirms zero of them fall in the added hunks), `release_cache.rs` shows 0 both before and after. The repo's baseline is simply not default-rustfmt-clean.
- **DRIFT-1.4** — verdict: resolved — the plan did not anticipate that `release_cache.rs`'s pre-existing unit tests construct `Entry` directly (`freshness_follows_ttl`) and pass bare `Ok(...)`/`Err(...)` closures. Both needed updating for the new shapes. Done via two local `ok()`/`err()` test helpers so the pre-existing cases keep reading exactly as before and their assertions are unchanged — the retain-on-failure and genuinely-empty-vs-unavailable behaviours are byte-identical.
- **DRIFT-1.5** — verdict: resolved — PLAN ITEM-7 said "render a distinct notice"; it did not say WHERE. Implementation placed it above the conditional block rather than inside the rows branch, because a rejected credential is equally true with rows, with stale rows, and with an unreachable feed — and burying it in the rows branch would hide it in the worst case (rejected AND the anonymous retry also failed ⇒ empty list, credential is the only actionable fact). Covered by the third component test, which asserts BOTH notices render together.
- **DRIFT-1.6** — verdict: resolved — the integration fixture revealed a trap the plan missed: `TestServer` inherits the test process's environment, and a developer runs the suite with `tests/.env.test` sourced (which sets an invalid `GITHUB_TOKEN`). The "no credential" positive control would therefore have silently been a "has credential" case, making TEST-6's distinguishability claim vacuous. `setup()` now explicitly blanks `GITHUB_TOKEN` for that arm. Recorded in INFRA_INTEGRATION.md §3.
- **DRIFT-1.7** — verdict: resolved — the report said BOTH tests in `version-discovery.spec.ts` fail on main. The RED run disproved half of it: `lists installable versions…` fails, `release-catalogue cache TTL persists…` **passes** (`1 failed, 1 passed`, exit 1). The plan's TEST-10 already existed to establish that status rather than assume it; no scope change, but the disproved half is reported rather than quietly dropped.
