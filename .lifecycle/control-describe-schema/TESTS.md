# TESTS — control-describe-schema

Tiers mirror the repo's existing pattern: in-source `#[cfg(test)]` for pure
logic, `server/tests/control_mcp/mod.rs` for the real JSON-RPC endpoint, and
`ui/tests/e2e/control/` for the real-LLM journey.

## Unit — the `$ref` inliner

- **TEST-1** (tier: unit) [covers: ITEM-1] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: a top-level `{"$ref": "#/components/schemas/X"}` is replaced by X's full body (its `properties`/`required` are present, the `$ref` key is gone)
- **TEST-2** (tier: unit) [covers: ITEM-1] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: a `$ref` two levels deep inside `properties` (object → property → property) is inlined, so a nested object's inner field names are present in the output
- **TEST-3** (tier: unit) [covers: ITEM-1] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: refs inside `items`, `additionalProperties`, `patternProperties`, `prefixItems` and `not` are each inlined
- **TEST-4** (tier: unit) [covers: ITEM-1] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: refs inside `allOf`, `oneOf` and `anyOf` variants are inlined, including the real nullable shape `anyOf: [{$ref}, {type:null}]`
- **TEST-5** (tier: unit) [acceptance] [invariant: INV-1] [covers: ITEM-1] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: for a multi-level fixture whose refs are reachable only through nested `properties`/`items`/`allOf`, the serialized result contains the string `#/components/` ZERO times and every leaf field name of every referenced component is present — i.e. the output is self-contained and complete, which fails if any traversal arm is missed
- **TEST-6** (tier: unit) [covers: ITEM-1] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: a `$ref` naming a component that does not exist yields `{"$comment": "unresolved $ref: …"}` (no panic, no silent pass-through of the dangling pointer), and a non-`#/components/schemas/` ref (e.g. an external URL) is left untouched rather than corrupted
- **TEST-7** (tier: unit) [acceptance] [invariant: INV-3] [covers: ITEM-1] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: a SELF-referential component (`Node.children.items -> Node`) terminates, and the result expresses the recursion as `{"$ref": "#/$defs/Node"}` with `Node` present in the root `$defs` — proving termination by a real self-reference, not by truncation
- **TEST-8** (tier: unit) [acceptance] [invariant: INV-3] [covers: ITEM-1] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: MUTUAL recursion (`A.b -> B`, `B.a -> A`) terminates and both A and B are resolvable within the emitted document (`$defs` closure is complete)
- **TEST-9** (tier: unit) [covers: ITEM-2] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: a chain deeper than `MAX_DEPTH` (and, separately, wider than `MAX_EXPANSIONS`) stops inlining and defers the remaining targets into `$defs` rather than continuing, and `schema_form` reports the cut
- **TEST-10** (tier: unit) [acceptance] [invariant: INV-2] [covers: ITEM-2] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: an input whose fully-inlined form exceeds `MAX_SCHEMA_BYTES` degrades to the compact `$defs` form — the output re-parses as JSON, is strictly smaller than the naive inline, contains `#/components/` ZERO times, and every `#/$defs/N` it references resolves inside its own `$defs` (bounded AND still self-contained AND still valid)
- **TEST-11** (tier: unit) [covers: ITEM-2] file: `src-app/server/src/modules/control_mcp/schema_inline.rs` — asserts: past the HARD byte cap, over-budget `$defs` entries become named `{"$comment": "omitted for size"}` placeholders in a deterministic order, the document still parses, and `schema_truncated` is true (never a mid-structure cut producing invalid JSON)
- **TEST-12** (tier: unit) [covers: ITEM-8] file: `src-app/server/src/modules/control_mcp/handlers.rs` — asserts: after the duplicate `resolve_schema_ref` is deleted, `validate_body` still resolves a `$ref` body schema (required-field and unknown-field rejection through the ref) AND still fails OPEN on a dangling ref — the pre-existing behaviour is preserved by the unified resolver
