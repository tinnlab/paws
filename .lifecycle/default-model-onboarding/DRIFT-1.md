# DRIFT-1 — implementation vs plan (+ design)

Authored DURING phase 5, as each item landed. Each entry reconciles the shipped
code against BOTH PLAN.md and the named design's invariants.

---

- **DRIFT-1.1** — verdict: impl-wins — **The step insert is NOT additive to the e2e suite; PLAN's ITEM-3 verdict said it was, and that was wrong.**
  Ten existing specs walk the wizard by clicking Next a fixed number of times and
  asserting `onboarding-step-<id>` between hops, so inserting `default-model`
  after `api-keys` shifted every downstream assertion. Measured, not guessed:
  `onboarding-wizard` (×2), `progress-api`, `onboarding-mcp-install`,
  `onboarding-api-key-save`, `guide-step-navigation`, `wizard-mcp-step`,
  `onboarding-to-first-chat`, `wizard-api-key-save`, `memory/onboarding-skip`,
  `memory/onboarding-enable`.
  **Resolution:** each patched with one pass-through hop. The plan was amended
  (Files to touch) rather than the placement — DEC-2's placement comes from the
  design, and moving a product surface to avoid test churn would be letting the
  suite dictate the design. Two spots needed hand-correction after the bulk edit:
  `guide-step-navigation` also walks BACKWARD (its Back sequence needed the extra
  hop too), and two specs sit inside an "API key saved" toast's lifetime where
  the surrounding code deliberately uses `press('Enter')` because a click gets
  intercepted — the inserted hop now matches.
  Desktop e2e was checked and traverses no wizard steps, so it needed nothing.

- **DRIFT-1.2** — verdict: plan-wins — **The originally-planned e2e install path was impossible; the plan was corrected BEFORE any code was written.**
  DEC-11 first proposed pointing the seeded repository row at a loopback fixture
  from the browser tier. `llm_repository/handlers.rs:225-251` makes a `built_in`
  row's `url`/`auth_type`/`name` immutable through the API — a deliberate
  security fix — and `tests/fixtures/test-context.ts` accepts no per-test env, so
  the only other route was editing shared harness (rule B3).
  **Resolution:** TESTS.md was rewritten and DEC-13 added before implementation:
  the install legs are proven at the integration tier (which supplies its own
  fixture-backed repository row, needing no production seam at all), the
  hard-to-reach render states at the component tier, and the browser tier proves
  placement / skip / restricted-user / 390px. Phases 3 and 4 were re-gated green
  after the rewrite. A debug-only clone-base override was considered and rejected:
  it would have added release-compiled surface area to buy nothing.

- **DRIFT-1.5** — verdict: impl-wins — The migration names its columns explicitly and carries `ON CONFLICT DO NOTHING`, where PLAN said "positional `INSERT … VALUES` mirroring `202607145040`".
  **Resolution:** kept, and the reasoning is in the file. The sibling is a
  squashed `pg_dump` baseline where positional `VALUES` was mechanical output;
  for a hand-written migration, naming the columns is what keeps it correct if
  the table gains one. `ON CONFLICT DO NOTHING` covers the upgrade case where an
  operator already added this URL by hand — their row wins instead of the upgrade
  failing. On a fresh database the insert always applies, which is the case INV-5
  is about, and TEST-2 asserts exactly one row carries the URL so the clause
  cannot silently hide a no-op.

- **DRIFT-1.8** — verdict: resolved — **Two defects found in my OWN test code while running it, both fixed rather than worked around.**

  a per-test `mockImplementation` — an earlier case's "flip enabled on update"
  leaked into the case asserting what happens when the enable does NOT take
  effect, making it pass for the wrong reason. Now `mockReset()` + an explicit
  default. (b) `DefaultModelStep.test.tsx` asserted `aria-label` on the element
  carrying `data-testid`; the kit puts the testid on the wrapper and the ARIA on
  the inner bar when a format function is supplied. Now asserted on the
  `role="progressbar"` node, where a screen reader would find it. Flagged here
  because a round of findings landing on this file is the GUARD-SUB signal to
  simplify rather than harden.
