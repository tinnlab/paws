# TESTS — background-in-conversation

Every ITEM is covered by ≥1 TEST; every `INV-N` is pinned by an `[acceptance]`
test that would FAIL if the invariant were violated.

## Backend

- **TEST-1** (tier: unit) [covers: ITEM-1] file: `src-app/server/src/modules/background_mcp/runs.rs` — asserts: `ListBackgroundRunsQuery` deserializes `conversation_id` from a query string — present ⇒ `Some(uuid)`, absent ⇒ `None`, and the other filters keep their defaults; a malformed uuid is rejected rather than silently dropped (a silently-dropped filter would widen the scope).
- **TEST-2** (tier: integration) [covers: ITEM-2] file: `src-app/server/tests/background_mcp/runs.rs` — asserts: with `conversation_id` set, the response `total` (from the COUNT query) equals the number of matching rows and paging is consistent across page 1 and page 2 — i.e. the disjoint predicate is applied to the count query too, not only the list query.
- **TEST-3** (tier: integration) [acceptance] [invariant: INV-3] [covers: ITEM-1, ITEM-2] file: `src-app/server/tests/background_mcp/runs.rs` — asserts: BOTH directions of the disjunction with runs seeded for conversation A, conversation B, and no conversation — `GET /api/background/runs` with no param returns ONLY the conversation-less run (never A's or B's), and with `conversation_id=A` returns ONLY A's run (never B's and never the conversation-less one). Fails if the filter degrades to the ordinary "ignore when absent" residual form.
- **TEST-4** (tier: integration) [covers: ITEM-2] file: `src-app/server/tests/background_mcp/runs.rs` — asserts: `conversation_id` composes with the pre-existing `status` / `kind` filters and stays owner-scoped — another user's run in the SAME conversation id is never returned.
- **TEST-5** (tier: unit) [covers: ITEM-3] file: `src-app/server/src/openapi/emit_ts.rs` — asserts: the `types_ts_parity` golden regenerates `types.ts` from the committed `openapi.json` and matches byte-for-byte, so the new `conversation_id` query param cannot be present in the spec but missing from the committed client.

## Frontend — unit

- **TEST-6** (tier: unit) [covers: ITEM-4] file: `src-app/ui/src/modules/background/stores/BackgroundRuns.store.test.ts` — asserts: `loadConversationRuns(cid)` calls `ApiClient.Background.listRuns` WITH `conversation_id: cid` and writes the result into `runsByConversation[cid]`; loading a SECOND conversation leaves the first conversation's slice intact (the split-pane clobber guard).
- **TEST-7** (tier: unit) [covers: ITEM-4] file: `src-app/ui/src/modules/background/stores/BackgroundRuns.store.test.ts` — asserts: a `sync:workflow_run` (and `sync:reconnect`) event refetches EVERY tracked conversation scope, each with its own `conversation_id`, and never issues an unscoped refetch. This is the regression guard for the rescued original's defect, where the sync reload's unscoped refetch replaced the panel's list with conversation-less runs and blanked the panel.
- **TEST-8** (tier: unit) [covers: ITEM-4] file: `src-app/ui/src/modules/background/stores/BackgroundRuns.store.test.ts` — asserts: `loadConversationRuns` self-gates on `hasPermissionNow(Permissions.BackgroundUse)` (no request at all without the grant → the no-403-on-reconnect invariant), and a rejected request records `errorByConversation[cid]` without clearing an already-loaded slice.
- **TEST-9** (tier: unit) [covers: ITEM-4, ITEM-5] file: `src-app/ui/src/modules/background/stores/BackgroundRuns.store.test.ts` — asserts: paging accumulates — `loadConversationRuns(cid, 2)` APPENDS to `runsByConversation[cid]` rather than replacing it, and `totalByConversation[cid]` drives the "Showing N of M" / Load-more condition.
- **TEST-10** (tier: unit) [covers: ITEM-4] file: `src-app/ui/src/modules/background/stores/BackgroundRuns.store.test.ts` — asserts: the live-refresh set is the MOUNT refcount, not the data map — loading a scope alone does NOT enlist it (so a session that visits N conversations does not fire N requests per run event), a retained scope IS refreshed, the refcount survives one of two consumers unmounting, the last release EVICTS the cached slice, a scope whose FIRST load failed is still retried on `sync:reconnect`, concurrent identical page-1 loads are deduped to one request, and an appended page de-duplicates a repeated row. (Re-pointed in FIX_ROUND-1: ITEM-11 became a deletion, so its old predicate + unit test are gone; ITEM-11 is now covered by TEST-16.)
