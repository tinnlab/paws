# DESIGN_FIDELITY — voice-model-bad-magic

One verdict per `INV-N` in PLAN.md's `## Invariants`, checked against what the
plan actually commits to build.

- **INV-1** — fidelity: UPHELD — ITEM-1 removes the condition that produced the error at all (real models now install), and ITEM-5 changes the *kind* of message a not-installed row can ever carry: a terminal download task renders as "Install failed — <reason>", an attempt-scoped statement, never a claim about a file on disk. The invariant is pinned by TEST-9 (`[acceptance]`), which asserts over the whole catalog that a not-installed model reports no file-validation error, and by TEST-12 (e2e) on the rendered page.

- **INV-2** — fidelity: UPHELD — ITEM-5 plus ITEM-12 cover BOTH cards on `/settings/voice`, so the page cannot present a per-model file error next to the "no models installed" empty state from either the models card or its runtime-binary twin. Pinned by TEST-12 (`[acceptance]`), which asserts the page-level composition — zero installed models AND zero per-model validation errors — rather than one card in isolation.

- **INV-3** — fidelity: UPHELD, with the antecedent verified FALSE — the invariant's imperative is "fix the CAUSE, not the display". ITEM-1 is the cause fix (the byte-order-wrong magic constant); ITEM-5/6/12 are explicitly downstream of it, not a substitute for it. The invariant's conditional clause ("if a failed download leaves a 0-byte file … AND clean up existing detritus") was tested against reality and does not apply: BUG_ANALYSIS E1 shows `voice-models/` is empty and E2 shows zero DB rows — the existing temp-then-move + cleanup-on-every-error path (`model.rs:396` tmp, `:445-448` remove-on-error, `:453` remove-on-invalid, `finalize_download` publish; `model_handlers.rs`'s `TempGuard` for upload) already works correctly. So there is no detritus to clean and no download-path lifecycle bug to fix. ITEM-2 nonetheless hardens the same path by giving the empty-response case its own error rather than mislabelling it. **Reported to the orchestrator rather than assumed**: no cleanup action is needed on the owner's live instance.

- **INV-4** — fidelity: UPHELD — ITEM-3 makes every rejection state what was found (observed leading bytes, hex + printable), what was expected (a `ggml`/`GGUF` container), and the corrective action; ITEM-2 ensures the *right* condition is named, so an empty response is no longer reported as bad magic. Pinned by TEST-5 (`[acceptance]`), which asserts all three components are present in the message for each distinct failure condition — an assertion that fails if the message regresses to a bare "bad magic".

- **INV-5** — fidelity: UPHELD — ITEM-4 applies the shared builder at the upload ingest point (`model_handlers.rs:565`), which already sits *before* the row write and behind `TempGuard`; the plan preserves that ordering and adds the missing distinct message for a 0-byte upload (today an empty upload is reported as "bad magic", which is false). Pinned by TEST-7 (`[acceptance]`): a 0-byte upload and a wrong-content upload are each rejected at ingest with their own clear message, with no `voice_models` row and no file left on disk.

- **INV-6** — fidelity: UPHELD — ITEM-6 suppresses the progress byte line for a failed download that transferred nothing (killing the naked "0 Bytes") and labels the count when the total is unknown; the catalog size stays on the row's metadata line where `AvailableModelsCard.tsx:212-216` already renders it. Pinned by TEST-6 (unit, `[acceptance]`) on the presentation helper across 0 / partial / complete, and observed on the rendered page by TEST-12.

- **INV-7** — fidelity: UPHELD — ITEM-7 replaces all fixture sites with bytes derived from the documented `GGML_FILE_MAGIC` u32 through one shared helper, so the *format* is the source of truth rather than the implementation. ITEM-8 adds the independent real-format pin. Pinned by TEST-8 (`[acceptance]`), which asserts the exact on-disk byte sequence `6c 6d 67 67` as a literal — a value taken from a real file (BUG_ANALYSIS E3), not from `has_whisper_magic`. If someone reverted ITEM-1's byte order, TEST-8 goes red even if every other test were rewritten to match the regression, which is precisely the D2 property the original tests lacked.

No `DROPPED` verdicts. No `AT-RISK` verdicts.
